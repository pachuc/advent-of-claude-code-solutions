# Problem Report: Disk Defragmentation - Region Counting (Part 2)

## Objective
Count the total number of distinct regions in the 128x128 disk grid. A region is a group of adjacent "used" squares that are connected orthogonally (not including diagonals).

## Context from Part 1
In Part 1, we generated a 128x128 grid representing disk usage where:
- Each square is either "free" (0) or "used" (1)
- The grid is generated by computing knot hashes for 128 rows (rows 0-127)
- For each row, the input to the knot hash is: `{key}-{row_number}` (e.g., "jxqlasbh-0", "jxqlasbh-1", etc.)
- Each knot hash produces a 32-character hexadecimal string
- Each hex character converts to 4 binary bits, giving us 128 bits per row
- The Part 1 answer was 8140 used squares total for the key "jxqlasbh"

## Part 2: Region Identification
Now we need to identify connected components (regions) in this grid.

### What is a Region?
- A region is a group of used squares (1 bits) that are all **adjacent** to each other
- **Adjacency is orthogonal only**: up, down, left, right (NOT diagonals)
- Every used square belongs to exactly one region
- A single isolated used square forms its own region
- Multiple adjacent used squares all count as a single region

### Example
For the test key "flqrgnkx", the first 8x8 section shows 9 distinct regions:

Important note: Region 8 appears in multiple disconnected places in this 8x8 view, but when considering the full 128x128 grid, all squares marked '8' are actually connected.

For the full 128x128 grid with key "flqrgnkx", there are **1242 total regions**.

## Input
- A key string (puzzle input): `jxqlasbh`

## Algorithm Requirements

### Step 1: Generate the Grid (Reuse from Part 1)
1. For each row (0-127):
   - Create input string: `{key}-{row_number}`
   - Compute knot hash (produces 32 hex characters)
   - Convert hex to binary (4 bits per hex char = 128 bits)
   - Store as a row in the grid

2. Result: A 128x128 grid of 0s and 1s

### Step 2: Count Connected Components
Use a graph traversal algorithm (e.g., BFS or DFS) to count distinct regions:

1. Initialize a region counter to 0
2. Create a visited/marked structure to track which cells have been assigned to a region
3. For each cell (i, j) in the 128x128 grid:
   - If cell is "used" (1) AND not yet visited:
     - Increment region counter
     - Perform flood fill (BFS/DFS) to mark all connected cells:
       - Start from current cell (i, j)
       - Mark it as visited
       - Check all 4 orthogonal neighbors (up, down, left, right)
       - For each neighbor that is:
         - Within grid bounds (0-127 for both dimensions)
         - "used" (value = 1)
         - Not yet visited
       - Add to queue/stack and continue flood fill
4. Return the total region count

### Adjacency Rules
- Only orthogonal connections count (4-connectivity):
  - Up: (i-1, j)
  - Down: (i+1, j)
  - Left: (i, j-1)
  - Right: (i, j+1)
- Diagonal connections do NOT count:
  - (i-1, j-1), (i-1, j+1), (i+1, j-1), (i+1, j+1) are NOT adjacent

## Expected Output
- A single integer representing the total number of regions in the 128x128 grid
